Why this rebuild happened

The bridge worked. The editorial layer didn't.

The first V1 piece through the full bridge — the may27_drift_mode_note pack — was structurally sound (signal in, pipeline ran, piece out, dashboard rendered). But the piece itself was unreadable for a first-time viewer.

What the V1 piece looked like (a 60-second reel)

"The Nifty is in drift mode — and history says guessing the next move is a coin flip."

Eleven numbers across the body. Four undefined jargon terms in the first thirty seconds (drift mode · stress · 89th percentile · RS / rotation). A takeaway that told viewers to "check your sector mix" and "right-size positions while stress is elevated" — which assumes the viewer already has positions, a sector mix, and a sizing framework. None of which Karan (the target persona) does.

That piece was technically correct and editorially useless. The skills had been written 6-8 weeks earlier for a subscriber audience, not for first-time viewers. The V2 rebuild fixes that gap from first principles.

The V2 pipeline

Four stages. Tight contracts between them.

Every piece flows through the same four stages, plus a final publish step. Each stage produces a strictly-shaped JSON artifact that the next stage reads. Prose only lives inside these artifacts, never between them.

[founder topic phrase] │ ▼ ANALYZE ── ~/kite-lab/scripts/analyse_topic.py │ produces a verified-data TopicDossier ▼ FRAME ── .claude/skills/frame-piece │ produces one-line FrameStatement ▼ WRITE ── .claude/skills/write-{snippet,daily-take,weekly-roundup} │ produces a structured ScriptDraft ▼ GUARD ── .claude/agents/voice-guard (independent subagent) │ returns a GuardVerdict ▼ PUBLISH ── scripts/publish.py (Bridge 2) ▼ [live at marketworks.in/library/<slug>]
Stage 1 · ANALYZE
analyse_topic.py
~/kite-lab/scripts/analyse_topic.py

Founder runs the CLI with a one-line topic phrase. The script routes the phrase to insight engine modules (5 categories), verifies the implied claim against real data, and emits a TopicDossier JSON.

  • 5 routing categories: sector · currency · concentration · watchlist · regime
  • Claim verification: confirms or refutes the phrase's implicit claim
  • Output: ~/kite-lab/data/topic_dossiers/<slug>.json
Stage 2 · FRAME
frame-piece skill
.claude/skills/frame-piece/SKILL.md

Picks the single sharp frame the piece will hang on. Generates three candidate frames internally, picks the sharpest, names 1-2 anti-frames the writer downstream should avoid.

  • One sentence, reducible to one feeling Karan walks away with
  • Defensible from at least one verified_fact in the dossier
  • Output: data/content_packs/<slug>/frame.json
Stage 3 · WRITE
write-{format} skill
.claude/skills/write-{snippet,daily-take,weekly-roundup}/

One writer skill per format. Each produces a structured ScriptDraft with format-specific required fields the voice guard checks against.

  • snippet: anchor_fact (one load-bearing number)
  • daily-take: causal_frame + cultural_anchor
  • weekly-roundup: load_bearing_variable + exactly 3 three_effects with mechanism per effect
Stage 4 · GUARD
voice-guard subagent
.claude/agents/voice-guard.md

Runs in an independent context window — no author bias. Walks 8 pass criteria against the script. Returns a structured GuardVerdict. If any criterion fails, the piece does not advance to publish.

  • Hard contract: do not rewrite · do not soften · do not pass conditionally
  • Cites a specific quote + criterion + fix for every failure
  • Output: data/content_packs/<slug>/guard_verdict.json
Stage 5 · PUBLISH (Bridge 2)
publish.py
scripts/publish.py

Refuses to run unless guard verdict.pass == true. Builds a PublishedPiece JSON in the shape the kite-dashboard expects at build time, writes BOTH the canonical record and a sync copy into the dashboard repo. Text-only — visual assets are a separate initiative.

  • Canonical: finance-content-os/published/pieces/<slug>.json
  • Sync: kite-lab/kite-dashboard/src/marketing-content/pieces/<slug>.json
  • Updates both manifests; Vercel deploys on next push to main
Three formats, three calibration scripts

Each format has a validated reference piece as its bar.

Skills pattern-match against validated examples, not abstract rules. The calibration scripts in brand/calibration/ are the literal benchmark each writer reproduces the density and arc of.

Format 1
Snippet
25-30 seconds
  • One term · tip · or current event
  • Hook (3-4s) · Body (15-18s) · Takeaway (3s) · CTA (2s)
  • ONE anchor number, not stat-stacked
Bar: brand/calibration/snippet_index_concentration.md
"Three stocks. The whole rally."
Format 2
Daily Take
45 seconds
  • Specific upmove · sector observation · structural pattern
  • Hook (4s) · Body (30s) · Takeaway (5s) · CTA (4s)
  • Causal frame + ONE cultural anchor line
Bar: brand/calibration/daily_take_defence_rally.md
"The trade most retail is 2 years late to."
Format 3
Weekly Roundup
75 seconds
  • Synthesised view of the week with one big frame
  • Hook (5s) · Body (55s) · Takeaway (10s) · CTA (5s)
  • ONE load-bearing variable · exactly 3 parallel effects with mechanism
Bar: brand/calibration/weekly_roundup_dollar_strength.md
"The week the dollar quietly broke things."
The eight drift defenses

How the rebuild doesn't fall off between runs.

Voice drift across sessions is the main risk for a creative pipeline at scale. The V2 layer is structurally designed against it. Each defense is implemented in code, not just hoped for. Full reasoning in tasks/content_redesign/REPEATABILITY.md.

1Anchor by example

Skills pattern-match against the 3 calibration scripts, not against rules in prose.

In: brand/calibration/ + every SKILL.md cites them
2Tight JSON contracts

Each stage's output is strictly shaped (TopicDossier, FrameStatement, ScriptDraft, GuardVerdict). Prose lives inside fields, not between them.

In: every SKILL.md's output schema
3Few-shot per skill

Every SKILL.md has a worked-examples section with full input/output pairs from calibration. Examples beat rules.

In: .claude/skills/*/SKILL.md
4Independent guard subagent

Voice-guard runs in a separate context window from the author. No shared rationalisation, no sunk-cost reasoning.

In: .claude/agents/voice-guard.md
5SessionStart hook

Auto-loads voice + personas + CTA inventory + calibration into every Claude session. Author starts with the bar in context from message 1.

In: .claude/hooks/load-brand-context.sh
6PreToolUse hook (deferred)

Designed-for: a hook that blocks Write on script.json paths unless voice-guard passes. Currently the write-* skills invoke the guard explicitly.

Deferred to v2.1
7Anti-pattern lists

Every SKILL.md has a Failure Modes section with concrete ❌ examples drawn from the V1 may27 piece. Negative examples sharpen the contrast.

In: every SKILL.md and brand/voice_v2.md
8Plugin packaging

Designed-for: bundle skills + agents + hooks as a Claude Code plugin for portability across machines/collaborators. Defer until 5-10 pieces ship.

Deferred to v2.x
CTAs · what every piece can point at

Four locked CTAs. No inventing new ones.

Every piece's call-to-action picks one of these four offerings. Each maps to a real, live Marketworks surface. Inventing a fifth is a guard-failure.

# Offering When to use
1 Follow @marketworks.in on Instagram Generic year-1 awareness CTA. Default if no other fits.
2 Sign up for the private beta — marketworks.in Product-curious pieces. Viewer wants more of the analysis.
3 4 momentum portfolios — marketworks.in Pieces about sector leadership, momentum, or portfolio thinking.
4 Daily market dashboard — marketworks.in/insights Pieces about market state · breadth · regime · cross-asset.
Founder workflow

From topic phrase to live piece — about 10 minutes.

1
Analyse the topic in kite-lab

You type a one-line phrase. The CLI routes it to insight engine modules and emits a verified-data dossier.

cd ~/kite-lab
.venv/bin/python scripts/analyse_topic.py --topic "your phrase here"
2
Open Claude Code in finance-content-os

The SessionStart hook injects voice + persona + CTAs + calibration into context. No need to remember to load anything.

cd ~/finance-content-os && claude
3
Pick the frame

In the session, invoke frame-piece on the dossier. Read the resulting frame. If it's not sharp, regenerate.

Invoke frame-piece on ~/kite-lab/data/topic_dossiers/<slug>.json with slug <pack-slug>.
4
Write the script + guard

Invoke the matching writer skill (snippet, daily-take, weekly-roundup) — based on the frame's format_hint. The skill auto-invokes voice-guard after writing.

Invoke write-snippet using the frame.
Skill writes script.json and guard_verdict.json
5
Read the guard verdict + your own gut check

If pass: true and you'd watch this on Instagram, proceed. If pass: false, the verdict lists which criterion failed and the suggested fix. Iterate.

6
Publish

Run the V2 publish script. Writes canonical record + syncs into the dashboard repo.

cd ~/finance-content-os
.venv/bin/python scripts/publish.py --slug <pack-slug>
7
Commit + push, Vercel deploys

Commit both repos, push, and the dashboard auto-deploys. Live at marketworks.in/library/<slug> in ~3-5 min.
